## Как провести следующий регресс

1. Зафиксировать адрес, опубликованный commit, устройство, ОС, точную версию браузера и фактическую ширину окна.
2. Скопировать шаблон в отдельную папку `runs/YYYY-MM-DD-release/`. Создать строки «кейс × окружение», первоначально все со статусом `NOT RUN`.
3. Выполнить Smoke. Затем Core и проверки изменённых функций. Перед существенным выпуском — Full и матрицу реальных устройств из плана.
4. Выполнять действия через интерфейс. Для каждого кейса записывать фактический результат; для отклонений — шаги и доказательства. Проверка исходного кода или зелёный CI сами по себе не дают ручной `PASS`.
5. Повторить исправленные дефекты, затем соседние сценарии. Закончить отчётом о выполненном объёме и оставшихся рисках.

Оба прогона выполнены **ассистентом через обычные клики, ввод и клавиши в браузере**, с визуальным осмотром и чтением скачанных файлов. Это не независимая человеческая приёмка и не запуск автоматических сценариев проекта. Проверки на настоящих телефонах и со средствами доступности остаются отдельной работой.
